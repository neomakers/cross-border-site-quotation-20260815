# Website Project Triage Evaluation Scenarios

All cases below are synthetic. They contain no customer identity, real domain, contact detail, confidential material, or commercial price.

## 1. Reference URL with immediate-quote pressure

**Sales request (English):** “Here is `https://reference.invalid/aurora`. Please quote it today. We need a 5-page brand site in Chinese and English; say what is included now.”

**Known facts:** One reference URL; five pages; two language packs. The request does not say which parts of the reference matter, whether an existing template is acceptable, whether there is motion or 3D, who supplies translations, or whether hosting is needed.

**Required loading:** Classification matrix, intake checklist, and contract routing because the request asks for a quote.

## 2. WebGL minimized as “just a few animations”

**Sales request (Chinese):** “客户说参考站只是几个动画。首页要跟随鼠标旋转的 3D 产品、粒子背景和滚动时切换镜头，移动端也要可用。”

**Known facts:** The requested homepage includes a real-time 3D product scene, particles, mouse-linked interaction, scroll-linked camera changes, and mobile support. Device coverage, performance budget, asset source, fallback behavior, and acceptance criteria are unknown.

**Required loading:** Classification matrix and intake checklist. Contract routing is not mandatory unless a contract, hosting, security, source, personal-data, payment, or API topic is introduced.

## 3. Static-looking site with business functions

**Sales request (English):** “The public site can look like a standard catalog. Customers must log in, pay invoices, and our staff need batch product upload and editing.”

**Known facts:** The public presentation may be class A or B, but login, payment, structured product data, and batch management are explicitly required. Payment provider, roles, data retention, API needs, hosting, security, compliance, and acceptance flows are unknown.

**Required loading:** Classification matrix, intake checklist, and contract routing because payment, backend, personal data, and likely hosting/security are involved.

## 4. Missing materials with a fixed launch date

**Sales request (Chinese):** “需要一个品牌官网，下个月第一个工作日必须上线。客户还没有文案、图片、产品资料或最终页面清单，先按常规方案推进。”

**Known facts:** The launch date is fixed, but content, assets, page count, page types, template permission, language count, hosting, acceptance devices, and decision process are unknown.

**Required loading:** Classification matrix and intake checklist. Contract routing becomes mandatory if the sales conversation adds quote, order, contract, hosting, ICP, security, source, personal data, payment, or API terms.

## 5. `A+` / `B-` boundary

**Sales request (English):** “Use our approved component library for a six-page site. We need a different content order on two pages, a custom brand palette, and static case-study pages; no login, CMS, payment, or custom animation.”

**Known facts:** Standard components are allowed, with limited rearrangement and brand styling. The request sits near the A/B boundary; the exact component changes, languages, content readiness, hosting, and acceptance devices are not yet confirmed.

**Required loading:** Classification matrix and intake checklist. Load anonymized cases only if precedent comparison is needed to resolve the adjacent-grade ambiguity.
